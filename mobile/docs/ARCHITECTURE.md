# LOXER Native Mobile App Architecture
## Hybrid Mobile Shell with Zero-Rebuild Auto Web Updates & Multi-Tenant Child Panels

---

### 1. Executive Summary & Design Philosophy
The LOXER mobile ecosystem utilizes a **Thin Native Shell + Remote Web Application** architecture. 
- **Core Principle:** *Install Once, Web Always Updated, Native When Needed*.
- **Business Agility:** 90–95% of features (job postings, employer tools, candidate portals, digital marketplace, Partner Center, Child Panels, themes, and layouts) live on the server and update instantly on web deployment.
- **Native Power:** Heavy hardware interactions (Biometrics, High-Precision Geolocation, Camera/Photo upload, Background Notifications, Document Downloads, Deep Linking, and Safe Area layouts) are handled by native Kotlin and Swift bridges.

### 2. Multi-Tenant Child Panel Architecture
A key requirement of LOXER is the capability to support thousands of independent **Partner Child Panels** (e.g. Andi Digital, Budi Rekrutmen, Rina HR) using a **SINGLE APK and SINGLE IPA**.

#### A. Single Origin Strategy
- All mobile clients connect primarily to `https://app.loxer.id` (with fallback to `https://loxer.web.id`).
- When a user logs in, the backend evaluates user credentials and returns:
  - `tenant_id`
  - `partner_slug`
  - `partner_name`
  - `branding_theme`
- The Web App renders the appropriate Child Panel identity (logo, accent colors, custom partner services) **inside the single web origin**.
- This guarantees session cookies, local caching, push tokens, and native bridges remain unified and secure.

#### B. Public Child Deep Link Translation
When a user clicks a public partner link like `https://andi.loxer.id/jobs/456` or `https://loxer.id/p/andi/jobs/456`:
1. The native App Links / Universal Links intercept the URL.
2. The native shell opens the primary webview at `https://app.loxer.id/jobs/456?tenant=andi`.
3. The server validates the partner signature and displays Andi's branded context safely.

### 3. Remote Web Auto-Update Engine
How the app updates without user intervention:

```
[App Launch]
    │
    ▼
[Native Splash Screen]
    │
    ▼
[Network Check] ──(No Internet)──► [Native Offline Screen (assets/offline.html)]
    │                                          │
    ▼ (Online)                                 ▼ (Reconnected)
[Fetch Remote Config] ◄────────────────[Auto-Recovery Listener]
(GET /api/mobile/config)
    │
    ├─► maintenance == true ───────► [Show Branded Maintenance Screen]
    │
    ├─► force_native_update == true ─► [Block UI & Direct to App Store/Play Store]
    │
    └─► Compare web_version with local last_web_version
            │
            ├─► Matches: Load cached WebView immediately (Sub-second start)
            │
            └─► Newer Web Version Detected (e.g. 2.7.1 -> 2.7.2):
                    │
                    ▼
                Check window.__LOXER_SAFE_TO_RELOAD__
                    │
                    ├─► false (User in transaction/checkout/attendance)
                    │     └─► Defer reload until navigation completes
                    │
                    └─► true: Controlled HTTP revalidation of index HTML
                              Hashed JS/CSS load fresh, state updated!
```

---

### 4. Cache & Asset Strategy
- **HTML Document:** Served with `Cache-Control: no-cache, must-revalidate`.
- **Hashed Assets:** JS and CSS files generated by Vite/Webpack contain content fingerprints (e.g. `index-CgvxQqRs.js`, `index-7g-6wEZV.css`). These can be cached aggressively for maximum speed.
- When server deploys a new build, the HTML document points to the new hashes. The app fetches the new bundle while old sessions transition smoothly.

### 5. Native Hardware & System Bridge Matrix
| Feature | Android Implementation | iOS Implementation | Web Fallback |
| :--- | :--- | :--- | :--- |
| **Platform Info** | `LoxerNativeBridge.getPlatform()` | `loxerNative.getPlatform` | User-Agent parse |
| **Location** | FusedLocationProvider / LocationManager | CoreLocation `CLLocationManager` | HTML5 Geolocation |
| **Camera** | Camera Intent + FileProvider | `UIImagePickerController` | `<input capture="camera">` |
| **File Picker** | Activity Result `ACTION_GET_CONTENT` | `UIDocumentPickerViewController` | `<input type="file">` |
| **Downloads** | Native Android `DownloadManager` | `URLSessionDownloadTask` + Share | Anchor `download` attr |
| **Sharing** | `Intent.ACTION_SEND` | `UIActivityViewController` | Web Share API |
| **WhatsApp** | `whatsapp://send?phone=...` | `whatsapp://send?phone=...` | `https://wa.me/...` |
| **External URL**| Chrome Custom Tabs | `SFSafariViewController` | `window.open('_blank')` |
| **Biometrics** | AndroidX `BiometricPrompt` | LocalAuthentication (Face ID/Touch ID)| Password fallback |
| **Push Token** | Firebase Cloud Messaging (FCM) | APNs + Firebase Messaging | Web Push Notification |
| **Haptics** | `Vibrator` / `VibratorManager` | `UIImpactFeedbackGenerator` | `navigator.vibrate()` |
